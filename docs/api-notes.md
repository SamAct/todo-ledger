## Tooling facts

- `claude plugin test` **does not accept a test-file argument.** Usage is `claude plugin test [dir]` (dir = the mod folder).
  `claude plugin test tests/smoke.test.ts` fails with `...\tests\smoke.test.ts: no such plugin folder`.
  Every later "Run: `claude plugin test tests/x.test.ts`" step must run the whole suite: `claude plugin test`.
- `claude plugin test` runs every `*.test.ts` / `*.test.tsx` under the dir.
- `claude plugin validate . --strict` lists hooks and `$` calls (`> ./register.ts calls: $.command.register`).
- `claude -p "/todos" --plugin-dir .` with no `command.run` hook prints:
  `todo-ledger registered /todos but no command.run hook answered it: add on("command.run", { command: "todos" }, ...)`.
- The engine also writes `tsconfig.json` at the plugin root (ignored by `.gitignore`).
- Test kit: plugins load at the test's first call on `$`; hooks the test registers with `on` sit beneath every plugin;
  "beneath them the bottom hook throws, naming its event" (so every `$` noun the mod touches needs a stub).
  `mock.env`, `mock.clock`, **`mock.store`** exist (`mock.store(on, entries?)` can replace the hand-written store stubs).
  `MockClock` has `now`, `advance`, `set`, `settle`, `sleep`.
- The smoke test's `command.register` stub returns `{ value: undefined }` and passes, although the typed value is `{ command: string }`.

## Signatures (quoted from the d.ts)

### $.env.get(name)
```ts
get: (name: string) => Promise<string | undefined>;
```
Async. `name` must be a string literal (validator lists it). Event `'env.get': { name: string }`.

### $.fs
```ts
read: FsReadCall;   // (path: string): Promise<string>; (path, { as: 'bytes' }): Promise<FsBytes>
write: (path: string, text: string) => Promise<void>;
list: (path?: string) => Promise<FsEntry[]>;
exists: (path: string) => Promise<boolean>;
```
- `write` is "Writes `text` to a file, creating it and its directories as needed."
- `read` "Rejects when missing, or over 4 MiB".
- `FsEntry = { name: string; kind: 'file' | 'dir' | 'other'; size: number; mtimeMs: number; isLink: boolean }`.
- Event args: `'fs.read': { path: string; as: FsReadAs }`, `'fs.write': { path: string; text: string }`,
  `'fs.list': { path: string }`, `'fs.exists': { path: string }`. Stub field names `e.path`, `e.text` are correct.

### $.process.run(argv, init?)
```ts
run: (argv: readonly string[], init?: ProcessRunInit) => Promise<ProcessRunResult>;
```
- `ProcessRunResult = { exitCode: number; stdout: string; stderr: string; isStdoutTruncated: boolean; isStderrTruncated: boolean }`.
- `init`: `{ cwd, env, stdin, timeoutMs }` (timeout 30 s default). "Rejects when the command cannot start or is still running then."
- Event: `'process.run': { argv: readonly string[]; init?: ProcessRunInit }` (stub `e.argv` correct).

### $.session.cwd() / id()
```ts
cwd: () => Promise<string>;
root: () => Promise<string>;
id: () => Promise<string>;
```
`cwd` = "the directory the session runs in"; `root` = "the session's project root ... where it started, or where /cd ... took it".

### $.model.complete(opts)
```ts
complete: (request: ModelCompleteRequest, options?: ModelCompleteOptions) => Promise<ModelCompleteResult>;
```
- `ModelCompleteRequest = { model: string; prompt: string; system?: string; maxTokens?: number; effort?: ModelEffort; timeoutMs?: number }`.
- `ModelCompleteResult`:
  `{ isAnswered: true; text: string; usage: ModelUsage }` |
  `{ isAnswered: false; reason: 'api-error'; status: number | null; error: ModelApiError; usage: ModelUsage }` |
  `{ isAnswered: false; reason: 'empty-reply' ... }` | `{ isAnswered: false; reason: 'aborted' ... }`.
  The answered arm has **no `reason`**; `usage` is a `ModelUsage` object
  (`{ input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens }`), never null.
- `timeoutMs` exceeded resolves `aborted`. "Only a request the engine refuses to send ... rejects."

### $.prompt.submit / fill
```ts
submit: EventCalls['prompt']['submit'];   // (input: PromptSubmitArgs) => Promise<PromptSubmitResult>
fill: (input: PromptFillArgs) => Promise<PromptFilled>;
```
- `PromptSubmitArgs = Omit<PromptSubmitInput, 'origin' | 'turnId' | 'wait' | 'context'> & { asUser?: true }` -> `{ text, attachments?, asUser? }`.
  Runs "a turn of its own, once the session is idle".
- `PromptFillArgs = { text: string; mode?: 'replace' | 'append' | 'insert'; decorations?: PromptDecoration[] }`.
- `PromptFilled = { isFilled: boolean; refusal?: 'no_composer' | 'dialog'; text: string; cursor: number }`.
  `no_composer`: "headless, or a surface that draws its own composer" (see Plan mismatches, desktop Draft).
- Hook-level results: `prompt.submit` -> `{ text, context?, origin? } | { drop }`; `prompt.fill` -> `{ isFilled, refusal? }`.

### $.ui.copy
```ts
copy: (args: UiCopyArgs) => Promise<UiCopyResult>;
```
`UiCopyArgs = { text: string; surface?: RenderSurface }` (object, **not** a string).
`UiCopyResult = { isCopied: true } | { isCopied: false; reason: 'no-surface' | 'no-clipboard' | 'refused' }`.

### $.ui.open / close / log / toast / invalidate
```ts
open: (pane: PaneOpenArgs) => Promise<UiOpenResult>;
close: (pane: PaneCloseArgs) => Promise<void>;
log: (text: string, options?: UiLogOptions) => void;
toast: (text: string, options?: ToastOptions) => void;
invalidate: (event: InvalidatableEventName) => void;
```
- `PaneOpenArgs = { id: string; title?: string; focus?: true; closeOnEscape?: true; holdToasts?: true; rows?: number; columns?: number }`.
- `UiOpenResult = { isPlaced: true } | { isPlaced: false; reason: string }`.
- `PaneCloseArgs = { id }`; `ui.close` event input `PaneCloseInput = { id: string; origin: { kind: 'plugin' | 'person' | 'unload' } }`.
- Events: `'ui.log': { text: string; to: 'transcript' | 'debug' }`, `'ui.toast': { text: string; timeoutMs?: number }`.

### $.store / $.clock
```ts
get: (key: string) => Promise<unknown>;
set: (key: string, value: unknown) => Promise<void>;
now: () => Promise<number>;
after: TimerCall;   // (ms: number, fn: () => void) => Timer   ({ cancel })
```
Events `'store.get': { key }`, `'store.set': { key; value }`, `'clock.after': { ms }`.

### $.tool.register / $.command.register
```ts
register: (tool: ToolSpec) => Promise<OpValueOf['tool.register']>;          // -> { tool: string }
register: (command: CommandSpec) => Promise<OpValueOf['command.register']>;  // -> { command: string }
```
- `ToolSpec = { name: string; description: string; inputSchema?: Record<string, unknown> }`; model calls it as `mcp__<plugin>__<name>`. "Rejects until the session binds, at `session.start`."
- `CommandSpec = { name: string; description: string; argumentHint?: string; immediate?: true }`. `argumentHint` and `immediate` are both supported.
- Event arg `'tool.register': Required<ToolSpec>` (stub `e.name`, `e.description` correct); `'command.register': CommandSpec`.

### command.run
- Input `CommandRunInput = { command: string; args: string; origin: PromptOrigin; presentation: CommandPresentation }`.
- `$.command.run` takes `CommandRunArgs` (`args?` optional, defaults `""`).
- Result `CommandRunResult = { text?: string; context?: readonly string[]; exitCode?: number; ref?: number }` (`{}` is valid).

### tool.call
- Input: `ToolCallInput = ToolCallEnvelope & AgentLoop`, the tool's arguments spread beside `tool` and `tool_use_id`; `agentId` set in a subagent.
- Result: `{ deny: string }` | `{ result: ToolResultOf<Name>; context?; ref?; text?; isReadOnly? }`.
- **TodoWrite** input (claude-code-tools, line 745):
  `TodoWrite: { todos: Array<{ content: string; status: "pending" | "in_progress" | "completed"; activeForm: string }> }`
  -> `e.todos` confirmed. Its result record is `{ oldTodos: [...], newTodos: [...] }`.

### turn.start / turn.complete
```ts
TurnStartInput = { text: string; turnId: string }
TurnStartResult = { turnId: string }
TurnCompleteInput = TurnCompleteFields & ({ reason: 'refusal'; refusal: TurnRefusal } | { reason: 'answer' | 'aborted' | 'error' })
TurnCompleteFields = { answer: string; durationMs: number; isAborted: boolean; turnId: string; agentId?: string; usage?: TurnUsage }
TurnCompleteResult = { text: string; usage?: TurnUsage }
```
- Reply text field confirmed: **`e.answer: string`** ("The assistant's final visible text this turn").
- `agentId` is set on a subagent's turns ("Every hook sees a subagent's turn"); "a subagent's run raises no `turn.start`".

### session.start
`SessionStartInput = { cwd: string; surface: RenderSurface | null; isInteractive: boolean }`; result `{ cwd: string }`.

### ui.render (AbovePrompt / Pane)
- `RenderResultOf = { [C in RenderComponent]: RenderElement }`: `next(e)` resolves to a `RenderElement` (typed non-null).
  The element union includes `{ type: 'engine'; ref: number }` ("The component core draws itself"; "0 draws the original props").
- AbovePrompt: "The band directly above the prompt input, where the surveys draw; the engine draws nothing of its own here."
  Raised on the terminal and desktop surfaces only. Props `{ hasSurvey, isWorking, maxRows, bodyColumns, scroll, view }`.
  What `next(e)` resolves to with no other plugin drawing is **not verified at runtime** (the test kit has no engine beneath
  the test's stubs). From the types, expect `{ type: 'engine', ref }` rather than `null`/`undefined`.
- Pane props `{ title, isFocused, bodyColumns, placement: 'dock' | 'inline', scroll, view }`; raised on every surface.
- `$.ui.resolve(e)` returns constructor functions `(props & { children? }) => RenderElement`, so `Button({...})` call style works.
- Tables: all surfaces have `Box, Text, Button, Link, Code, Markdown`; `Input` and `Select` on terminal, desktop, vscode, **not mobile**.
- `ButtonProps`: `key?, label?, hotkey? (one digit or lowercase letter), action?, plain?: true, dimColor?: boolean, variant?, role?, autoFocus?: true, hover?, onPress`.
- `InputProps`: `key, label?, placeholder?, value?, submitLabel?, autoFocus?: true, onInput?, onSubmit: (value: string, e) => void`.
- `SelectProps`: `key, label?, options: readonly { value: string; label?: string }[], value?, autoFocus?: true, onSelect: (value: string, e) => void`.
- `BoxProps` includes `flexDirection`, `gap`, `columnGap`, `rowGap`, etc.
- Test kit `ui.find({ text })` matches "a Button or Link's label" as shown text, but `type: 'Text'` will not match a Button.

## Plan mismatches

Where the plan's code (Tasks 3-9, `tests/fakes.ts`) has to differ from this build:

1. **All tasks - test command.** `claude plugin test <file>` is not supported; run `claude plugin test` (whole suite) at every "run to verify failure / run tests" step. Expected failures show up as one failing file among passing ones.
2. **Task 9 `doStart` - `$.ui.copy(text)` is wrong.** Use `$.ui.copy({ text })` (optionally `surface: e.surface` from the press). Two places: the `copy` branch and the terminal fallback. `tests/fakes.ts`'s `ui.copy` stub already reads `e.text`.
3. **Task 7 - scan on subagent turns.** `turn.complete` fires for subagent turns too (`e.agentId` set). `runScan` must be skipped when `e.agentId !== undefined`, and it should also skip `e.reason !== 'answer'` (aborted / error / refusal). Otherwise every subagent's long answer triggers a Haiku call.
4. **Task 7 tests - `turn.start` / `turn.complete` inputs.** `$.turn.start({ turnId: 't1' })` lacks the required `text`; use `$.turn.start({ text: '', turnId: 't1' })`. `$.turn.complete({...})` lacks the required `reason`; add `reason: 'answer'`. `usage: null` is not a valid `TurnUsage`; omit `usage`.
5. **tests/fakes.ts - `model.complete` stub shape.** Answered arm is `{ isAnswered: true, text, usage: ModelUsage }`, no `reason`; unanswered arm needs a real reason (`'api-error'` with `status`, `error`, or `'empty-reply'`/`'aborted'`). Use e.g. `usage: { input_tokens: 0, output_tokens: 0, cache_read_input_tokens: 0, cache_creation_input_tokens: 0 }`. Task 7's `runScan` reads `r.reason` only when `!r.isAnswered`, which matches.
6. **tests/fakes.ts - `process.run` stub value** lacks `isStdoutTruncated: false, isStderrTruncated: false`; add them.
7. **tests/fakes.ts - `fs.list` stub entries** lack `mtimeMs`; add `mtimeMs: 0`.
8. **tests/fakes.ts - register stubs.** `command.register` value is `{ command: string }`, `tool.register` value is `{ tool: string }`; the plan returns `{ value: undefined }`. The smoke test passes with `undefined`, so this is cosmetic unless the mod reads the value; prefer `{ value: { command: e.name } }` / `{ value: { tool: 'mcp__todo-ledger__' + e.name } }`.
9. **tests/fakes.ts - store stubs** can be replaced with `mock.store(on)` (exists in this build). Optional.
10. **Task 3 `ensureDir`** - `$.fs.write` already creates parent directories, so the `cmd /c mkdir` call is unnecessary. Optional simplification; keep the tmp + `move /y` write as the Global Constraints require.
11. **Task 8 band - surveys.** AbovePrompt is "where the surveys draw"; the hook should `return next(e)` when `e.props.hasSurvey` is true (the shipped band example does). Add that guard.
12. **Task 8 band - empty `next(e)`.** `next(e)` is typed `RenderElement`, never null; the `theirs ? [mine, theirs] : [mine]` guard is harmless. Runtime value with nothing beneath is unverified (see ui.render above); the test stub's `Text 'engine'` stands in for it.
13. **Task 8 pane - `Select` `onSelect` typing.** `onSelect` is `(value: string, e) => void`; `(v: Kind) => ...` needs `(v: string) => { newKind = v as Kind }`. Type-only; runtime same.
14. **Task 8 pane - mobile.** `Pane` is raised on every surface, but mobile's table has no `Input` / `Select`. The hook should only draw `Input`/`Select` when `e.surface !== 'mobile'` (or skip the add row and chooser there). The plan's tests mount terminal/desktop only, so tests still pass.
15. **Task 8 / Task 9 tests - text queries.** `ui.find({ type: 'Text', text: /agent thing/ })` will not match item titles, which the plan draws as `Button` labels. Use `ui.find({ key: 'title-' + id })` or `ui.find({ type: 'Button', text: /agent thing/ })` as the plan's fallback note says.
16. **Task 9 Draft on desktop - risk, unverified.** `PromptFilled.refusal` documents `no_composer` for "a surface that draws its own composer". The desktop may refuse `$.prompt.fill`; `doStart` should check `isFilled` and fall back to copy + toast when false. Confirm in Task 10 Step 5.
17. **Task 3/6 project key - optional.** `$.session.cwd()` is the working directory; `$.session.root()` is the project root and does not move with a shell `cd`. Consider `root()` for the `project` field. Not required.
18. **Task 6 - TaskCreate/TaskUpdate.** This build also declares `TaskCreate` / `TaskUpdate` built-in tools beside `TodoWrite`. If the session's model uses the Task tools instead of TodoWrite, the TodoWrite mirror captures nothing. Not verified which one this build's model uses by default; check during Task 10.
